## 🛠️ 重磅开源项目 & 实用工具 (Tools & Projects)

### 1. [[vLLM]] - 超高吞吐量与显存利用率的 LLM 推理服务引擎
- **项目定位**：伯克利开源的大模型推理和服务引擎，当前行业落地的事实标准之一。
- **GitHub 仓库**：[vllm-project/vllm](https://github.com/vllm-project/vllm)（Star 40k+）
- **核心能力与优势**：
  - **PagedAttention**：首创类似操作系统虚拟内存的分页机制，彻底解决 KV 缓存（Key-Value Cache）碎片化问题，显存浪费降低到 4% 以下。
  - **连续批处理（Continuous Batching）**：迭代级请求动态批处理，吞吐量比 Hugging Face 原生高 10~24 倍。
  - **多 LoRA 动态加载与投机采样（Speculative Decoding）**：单实例支持并发挂载数十个不同微调权重，极大节省多租户部署成本。
- **适用场景**：私有化大模型部署、高并发 API 网关后端、低延迟生产服务。
- **详细沉淀卡片**：👉 [[vLLM]]

---

### 2. [[LiteLLM]] - 统一 100+ 大模型 API 的企业级路由网关
- **项目定位**：轻量级统一调用 SDK 与代理网关（OpenAI 格式标准化）。
- **GitHub 仓库**：[BerriAI/litellm](https://github.com/BerriAI/litellm)（Star 20k+）
- **核心能力与优势**：
  - **接口极简归一**：无论底层是 OpenAI、Anthropic Claude、Google Gemini、DeepSeek 还是本地 vLLM/Ollama，一律以统一的 `completion(...)` 或 OpenAI 兼容格式调用。
  - **企业级代理功能**：开箱即用支持 API 密钥管理、速率限制（Rate Limiting）、失败重试（Retry & Fallback 故障降级）、成本追踪与团队配额管理。
- **适用场景**：多模型混用架构、企业内部 AI 平台网关、防止单供应商锁定（Vendor Lock-in）。
- **详细沉淀卡片**：👉 [[LiteLLM]]

## 💡 工程实践与架构设计 (Engineering Practices)

### 1. [[RAG 生产环境优化：多路召回与 Rerank 最佳实践]]
- **解决痛点**：传统纯向量检索（Dense Vector Retrieval）面临三大致命问题：
  1. 专有名词/缩写/型号搜索命中率极低（如产品编号 `X-9000`）；
  2. 语义相似但不相关的段落误召回（维度坍缩）；
  3. Top-K 文本块冗余，直接塞给 LLM 导致“迷失在中间（Lost in the Middle）”。
- **工程解法（经典生产级三段式）**：
  - **第一阶段（多路召回）**：BM25（关键词高精精确匹配） + 稠密向量（语义语义理解）并行检索；
  - **第二阶段（倒数秩融合 RRF）**：统一两路得分，消除不同算法的分值量纲差异；
  - **第三阶段（交叉编码器 Rerank）**：使用 Cross-Encoder 模型（如 `bge-reranker-large`）对 Top 20 进行深度打分，最终取最具相关性的 Top 3~5 喂入 LLM。
- **详细落地卡片**：👉 [[RAG 生产环境优化：多路召回与 Rerank 最佳实践]]
